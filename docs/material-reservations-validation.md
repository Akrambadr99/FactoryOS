# Material reservations: local delivery evidence

Validated on 2026-09-30 with Node 20.19.5 on Windows, starting from commit `43c0625910fc9b07b0706d096f4dc8bc3ed1c040`. This delivery changes FactoryOS only. It introduces a local, single-process material reservation service and a connected React workspace, not a production deployment.

## Delivered workflow

- Explicit connection and saved-order synchronization; existing browser execution records remain unchanged.
- Shared demo-stock allocation, one active hold per order/lot, validated releases and retained history.
- Atomic file publication, exclusive process ownership, revision conflicts and persistent idempotency receipts.
- Preserved per-order drafts, captured-request retry, explicit conflict recovery and protection against older responses.
- URL selection, filtering, sorting, pagination and Back/Forward behavior, including rapid selection followed by filtering.
- Responsive master-detail layout, visible labels, keyboard release confirmation, focus restoration, live feedback and reduced motion.

## Chromium and visual evidence

The six new journeys exercise reconnect with hidden selection, persistence after browser reload, competing-view conflict recovery, a dropped real-service acknowledgement followed by an identical retry, keyboard cancellation and focused release-failure retry, and responsive operation with an empty filtered list.

Screenshots are regenerated by the responsive journey at `test-results/reservations-1440.png`, `test-results/reservations-820.png` and `test-results/reservations-390.png`. They are local test artifacts, not committed assets. Desktop and mobile captures were inspected; automated checks also verified no horizontal overflow at tablet/mobile widths and keyboard skip-link behavior.

During the first full browser run, rapid selection followed by filtering exposed a stale URL update. A deterministic component regression failed before the fix and passed afterward. The final full Chromium run passed without adding waits to conceal that sequence. A separate regression verifies editing after Back/Forward navigation.

Final accessibility review also reproduced focus landing on the page body after release failure. A failing regression drove the fix: Retry receives focus when the closed dialog cannot restore its disabled trigger, while a delayed failure preserves focus in an actively edited draft. The browser release journey verifies the focused retry sends the exact original request and records its reason once.

## Remaining boundaries

This phase uses simulated inventory, explicit browser-order synchronization and a bounded file-backed ledger. It has no login, user roles, tenant isolation, authoritative production inventory, database migration, backup service or cloud deployment. Existing execution gates are deliberately not automatically released by a reservation. In-page drafts and pending attempts are not persisted across navigation or browser reload.

The next phase should establish database-backed authoritative orders and inventory, with a reviewed migration contract, before multi-user authentication and inventory receipts/consumption are enabled. See [the runbook](material-reservations.md) for startup, capacity limits and fail-closed recovery guidance.
